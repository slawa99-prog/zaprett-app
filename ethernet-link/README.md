# Ethernet Link — 2.1-test1

Android-приложение для чтения согласованной скорости USB-Ethernet и проверки
интернета через встроенную страницу Яндекс Интернетометра. Android 8.0+;
APK включает arm64-v8a, armeabi-v7a, x86 и x86_64.

## Что изменилось

* Две вкладки: «Линк» и «Интернетометр». Версия — внизу экрана.
* Android может запомнить приложение для адаптера через «Всегда использовать».
  USB_DEVICE_ATTACHED и точные device filters объявлены в манифесте. Приложение
  автоматически запрашивает доступ один раз на подключение, если его ещё нет.
  После отказа повторный запрос доступен по кнопке, до нового подключения.
  Сохранение выбора контролирует Android; одинаковое поведение всех прошивок
  не гарантируется. Root и самостоятельной выдачи привилегий нет.
* Прямые USB-запросы для RTL8152, RTL8153, RTL8156 и AX88179/AX88178A,
  включая известные OEM-идентификаторы: всего 40 точных VID:PID.
* versionCode 4; пакет com.slawa.ethernetlink.v2 и ключ v2 сохранены.

## Поддержка USB

| Семейство | Чтение | Скорости, Мбит/с |
| --- | --- | --- |
| RTL8152, 0bda:8152 | PLA_PHYSTATUS | 10 / 100 |
| RTL8153, 0bda:8153 | PLA_PHYSTATUS | 10 / 100 / 1000 |
| RTL8156, 0bda:8156 | PLA_PHYSTATUS | 10 / 100 / 1000 / 2500 |
| Realtek OEM из r8152.c | PLA_PHYSTATUS | До 2500, согласно статусу |
| AX88179 / AX88178A и совместимые OEM | PHY_PHYSR, page 0 | 10 / 100 / 1000 |

Точный список — UsbAdapterCatalog.java и res/xml/usb_devices.xml. ASIX проверяется
только в vendor-режиме интерфейса FF/FF/00, как в драйвере Linux v6.12.
Названия товаров не используются для определения чипа. Наличие Ethernet в
Android не означает поддержку прямого USB-чтения. Неизвестные чипы, включая
AX88772 и новые 5/10G Realtek, не опрашиваются наугад; остаётся sysfs/ethtool.

Все управляющие USB-запросы — IN/VENDOR/DEVICE через endpoint zero:

* Realtek: request 0x05, value 0xe908, index 0x0133, 4 байта, little endian.
  LINK 0x02, FULL 0x01, 10/100/1000/2500: 0x04/0x08/0x10/0x0400.
* ASIX: request 0x02, PHY ID 3, register 0x11, 2 байта. LINK 0x0400,
  FULL 0x2000, speed mask 0xc000. Register 0x1f читается до/после для
  проверки page 0. При другой странице результат неизвестен, записи нет.
* Два свежих чтения скорости; конечный таймаут 500 мс на запрос.
  Короткий ответ, 0xffff, противоречивые биты, смена скорости/дуплекса,
  неподходящая PHY page и отключение в ходе чтения не выдаются за точную скорость.

Нет OUT-запросов, claimInterface, принудительного отвязывания драйвера,
setConfiguration, reset, записи регистров или переключения software MII.
UsbManager.hasPermission проверяется перед чтением. Дескриптор закрывается.
USB-результат относится к адаптеру, а не к предположительно связанному eth0.
При нескольких поддерживаемых адаптерах программа просит оставить один.

## Интернетометр

Официальная страница https://yandex.ru/internet/ загружается в Android WebView
только при открытии вкладки. Пользователь сам нажимает «Измерить» на странице.
Нет автоматического теста при USB-подключении, запуска браузера, извлечения
результатов из внутренних API Яндекса или отправки диагностического отчёта.
Сайт Яндекса получает обычные данные браузерного посещения и тестовый трафик.

Для измерения именно Ethernet используется AndroidX WebKit ProxyController
и локальный CONNECT relay. Он слушает только 127.0.0.1; каждое исходящее
соединение и DNS-запрос выполняются через выбранный Ethernet Network.
HTTPS и WSS проходят без расшифровки TLS, JavaScript bridge отсутствует.
Правило WebView не содержит direct fallback/bypass; implicit bypass отключён.
После потери сети привязанные сокеты перестают работать. При уходе со вкладки
или из приложения WebView уничтожается, relay и все его соединения закрываются.
Закрытое proxy rule сохраняется до следующего запуска вкладки, чтобы поздние
запросы WebView не ушли в сеть телефона по умолчанию.

Если Ethernet недоступен, подключено несколько Ethernet-сетей, включён VPN
или WebView не поддерживает PROXY_OVERRIDE, замер не запускается. Приложение
показывает причину. При устаревшем WebView требуется его обновление. Сайт может
показывать собственную CAPTCHA/ошибку. Вход в Яндекс и внешнее приложение не нужны.
Скорость через WebView/relay нуждается в сравнении на реальном телефоне,
особенно на гигабите; это не калиброванный измерительный прибор.

## Проверки и ограничения

На Samsung S24 Ultra / Android 16 пользователь подтвердил в 2.0-test2 прямое
чтение RTL8153 на известных портах 100 и 1000 Мбит/с. Sysfs и SIOCETHTOOL
на этом телефоне закрыты EACCES. Оценка Android 100000 Kbps не используется
как доказательство скорости физического линка.

Новые семейства проверены программными тестами протоколов; физические адаптеры
не были доступны для проверки. Штатный драйвер телефона должен поддерживать
адаптер. Поддержка всех USB-чипов, смартфонов и прошивок не заявляется.

Проверить на телефоне после обновления:

1. Разрешить доступ и отметить «Всегда использовать», если пункт показан;
   переподключить адаптер. Отказ и ручной повтор не должны зацикливать диалог.
2. Сравнить 100 и 1000; выдернуть RJ45 — прежняя скорость должна исчезнуть.
3. Открыть Интернетометр, запустить замер, проверить загрузку/отдачу.
4. Отключить Ethernet при доступном Wi-Fi/LTE — замер должен остановиться.
5. Другой чип: при неопределённой скорости скопировать диагностику.

## Сборка

JDK 17, Gradle 8.9, SDK 35, NDK 27.2.12479018, CMake 3.22.1.

```sh
bash tests/run.sh
gradle :app:assembleRelease
```

GitHub Actions собирает unsigned APK. Постоянный ключ v2 хранится вне репозитория
и применяется отдельно через apksigner. Приватный ключ не включать в git/CI.

Тесты: native GLINKSETTINGS handshake под ASan/UBSan; LinkDecision против
устаревших/неизвестных значений; RTL8153 regression; Realtek/ASIX decoder,
точные IN-запросы, PHY page guards; 40-ID filters; жизненный цикл USB-разрешения;
CONNECT двунаправленная передача, остановка и отсутствие сетевого fallback.
