Ethernet Link — постоянный доступ к USB на Samsung
Утилита 1.0-test2 для Windows и уже настроенного беспроводного ADB

ИСПРАВЛЕНО В TEST2
Телефон теперь выбирается из действующих подключений ADB. Поддерживаются как адреса
IP:порт, так и автоматически найденные имена adb-..._adb-tls-connect._tcp.
При одном подключении вводить ничего не нужно, при нескольких — выбирается номер.
Механизм настройки USB-разрешения не изменён.

ЗАЧЕМ ЭТО НУЖНО
На проверяемом Samsung система сохраняет Ethernet Link как приложение для адаптера,
но пропускает обработку его подключения с сообщением «because of Dex». Поэтому
обычное разрешение снова требуется после переподключения. Сам DeX при этом выключен.

Эта отдельная утилита просит Android сохранить постоянный USB-доступ для установленного
Ethernet Link и подключённого Realtek RTL8153 (0bda:8153). Она работает через уже
разрешённую пользователем отладку ADB, не устанавливает новое приложение и не требует root.
Автоматический запуск Ethernet Link она НЕ восстанавливает: приложение нужно открыть вручную.

ВАЖНО О СТАТУСЕ ПРОВЕРКИ
Код скомпилирован; проверки ограничения доступа к нужному приложению и адаптеру пройдены.
На физическом Samsung утилита ещё не проверена. Прошивка может отклонить этот системный
запрос. Нужна проверка после переподключения, затем — после перезагрузки телефона.
Принятый системой запрос сам по себе не доказывает сохранение после перезагрузки.

КАК ЗАПУСТИТЬ
1. Оставь установленный Ethernet Link 2.3-test2. Удалять или обновлять его не нужно.
2. Распакуй архив. Скопируй START.cmd и ethernet-usb-access.jar в папку platform-tools,
   туда, где лежит adb.exe. При желании скопируй туда и эту инструкцию.
3. Телефон и компьютер должны быть соединены беспроводным ADB, как при сборе отчётов.
   Вставь в телефон ровно один адаптер RTL8153. Не нажимай в приложении «Разрешить USB».
   Если разрешение уже было выдано, переподключи адаптер перед проверкой.
4. Открой START.cmd двойным щелчком. Администратор Windows не требуется.
5. Утилита сама найдёт подключённый телефон. Если подключений несколько, введи номер
   своего Samsung в списке. Если он показан дважды — по IP:порту и по имени adb-... —
   можно выбрать любую из этих двух строк. Вручную вводить IP и порт не нужно.
6. Выбери 2 (GRANT), затем Y, чтобы применить постоянное разрешение.
7. При успехе появятся строки:
     persistent_permission.setter=ACCEPTED
     current_access.after=true
     RESULT=GRANT_ACCEPTED
   Сохрани копии usb-access-result.txt и usb-access-state.txt из папки platform-tools.
8. Вынь адаптер и вставь снова. Вручную открой Ethernet Link. Не нажимай «Разрешить».
   Если скорость сразу появилась, проверь ещё пару переподключений.
9. Чтобы проверить через ADB, снова открой START.cmd, при необходимости выбери телефон
   и нажми 1 (CHECK). В результате должно быть current_access.before=true.
   Этот пункт только читает состояние. Он не выдаёт разрешений.
10. После успешной проверки можно перезагрузить телефон и повторить проверку в приложении.
    После перезагрузки беспроводной ADB может требовать повторного подключения.

ЕСЛИ НЕ ПОЛУЧИЛОСЬ
При RESULT=ERROR, SecurityException, NoSuchMethodException или прежнем запросе USB
пришли usb-access-result.txt и usb-access-state.txt. Эти файлы содержат техническое
состояние USB и названия приложений; публиковать их в общий доступ не нужно.
Если утилита не нашла телефон, пришли usb-access-devices.txt. Устройство со статусом
offline или unauthorized не выбирается; нужно восстановить подключение ADB.
Каждый запуск перезаписывает отчёты: копируй нужный результат до следующего запуска.
Не нужно наугад отключать DeX, защиту телефона, менять системные файлы или получать root.

ЧТО ИМЕННО ИЗМЕНЯЕТСЯ
Изменяется только запись постоянного разрешения Android USB для UID Ethernet Link,
пользователя-владельца (user 0) и фильтра текущего адаптера RTL8153. Фильтр формирует Android
по данным устройства: такой доступ может распространяться и на другой неразличимый
для системы адаптер с теми же дескрипторами. Это не разрешение на все USB-устройства.
Перед изменением проверяются Samsung, Android 12+, UID shell, профиль владельца,
пакет com.slawa.ethernetlink.v2 и сертификат подписи наших сборок. UID приложения
берётся с телефона, а не зашит в утилиту. При нескольких RTL8153 утилита откажется работать.
Утилита не захватывает USB-интерфейс, не сбрасывает адаптер и не записывает его регистры.
Временный JAR удаляется с телефона после выполнения. Фонового процесса не остаётся.
После удаления и повторной установки приложения его UID может измениться: тогда может
понадобиться повторная настройка. Обычное обновление APK с той же подписью сохраняет UID.

БЛОКИРОВКА ДОСТУПА
Пункт 3 (BLOCK), затем Y сохраняет явный ЗАПРЕТ доступа Ethernet Link к этому адаптеру.
Это не возврат режима «спрашивать каждый раз». Для повторного разрешения используй
пункт 2 (GRANT). CHECK ничего не меняет.

ТЕХНИЧЕСКИЕ СВЕДЕНИЯ
Используется системный IUsbManager.setDevicePersistentPermission через Binder API
текущей прошивки. Проверка — hasDevicePermissionWithIdentity. Запросы выполняются
от ADB shell с системным разрешением MANAGE_USB, а не от обычного приложения.
Коды Binder-транзакций не угадываются; при отсутствии API или отказе системы утилита
завершается с ошибкой. В dumpsys usb запись видна в device_persistent_permissions.
Автоматический запуск по USB_DEVICE_ATTACHED и постоянное разрешение — разные механизмы.
